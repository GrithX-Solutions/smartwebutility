Convert JSON to XML with predictable mapping rules

JSON and XML represent data differently, so there is no single universal conversion that every application interprets the same way. This tool uses documented mapping rules instead of pretending the formats are perfectly interchangeable.

Objects become child elements

Each JSON object member becomes an XML child element. Nested objects create nested XML structure under the same key name.

Arrays repeat elements

An array stored under a key produces repeated elements with that key. If the entire JSON document is an array, values are wrapped by the configurable root and item element names.

Primitive values become text

Strings, finite numbers and booleans become XML text content. JSON null becomes an empty element because XML has no native JSON-null value.

Invalid XML key names are preserved

If a JSON key cannot be used directly as an XML element name, it is represented as <property name="original key"> so the key is not silently discarded.

Why JSON to XML is not lossless by default

JSON distinguishes strings, numbers, booleans and null values, while plain XML element text does not automatically preserve those JSON types. Arrays also have no single required XML representation. This converter prioritizes readable XML structure; applications that require round-trip type preservation should use an agreed XML schema or type-annotation convention.

Root element and array item names

XML documents require one root element. The default is root, but you can choose another valid XML-style name such as response, catalog or records. Root-level arrays use the configurable item name, while arrays attached to an object key repeat that object's key.

JSON keys that are not valid XML names

JSON allows member names such as "first name", "123" or strings containing punctuation that are unsuitable as simple XML element names. Rather than changing them silently, the converter uses a generic property element with a name attribute containing the original key.

Escaping special XML characters

Text values and preserved key names are escaped for XML. Characters such as ampersands and angle brackets are encoded so JSON strings become XML text rather than accidental markup.

What this converter does not infer

It does not guess XML attributes from JSON keys, generate an XSD, create namespaces, infer SOAP envelopes, or apply vendor-specific JSON↔XML policies. Those transformations depend on an external schema or application contract and should not be invented automatically.

Frequently asked questions

How are JSON arrays converted to XML?

Arrays under an object key repeat that key as an XML element. A root-level array uses the configurable item element name.

Does JSON null have an XML equivalent?

No universal equivalent exists. This converter writes an empty element for JSON null.

Can JSON keys become XML attributes?

Not automatically. Attribute mapping requires an application-specific convention, so this tool does not guess it.

Can I open a JSON file?

Yes. Local JSON files up to 5 MB can be opened and converted in the browser.

Is the JSON uploaded?

No. Conversion runs locally in browser JavaScript.
