What HTTP response headers tell you

Response headers provide metadata about a web request. They can reveal content type, caching behavior, redirects, server information, compression, security policies and CDN behavior without requiring you to inspect the full page body.

Headers worth reviewing

content-type identifies the returned media type, cache-control controls caching behavior, location identifies redirect targets, and security headers such as strict-transport-security or content-security-policy can affect browser security. CDN and reverse-proxy platforms may add their own diagnostic headers.

Security interpretation

The presence of a security header is not by itself proof that a site is secure, and the absence of one header does not automatically mean a vulnerability exists. Configuration must be evaluated in the context of the application and how browsers use the response.

Frequently asked questions

Why is the Server header missing?

Many platforms intentionally hide or minimize server-identification headers. Reverse proxies and CDNs may also replace origin headers.

Why are browser headers different from this check?

Content negotiation, cookies, geographic routing, authentication and CDN rules can cause different clients to receive different responses.
