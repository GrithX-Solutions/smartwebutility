Convert cURL to Python, fetch, Axios or PHP

The converter reads a cURL command as an HTTP request description and generates equivalent starter code for a selected client. It is designed for API examples copied from documentation, browser developer tools, terminal history and support tickets.

cURL to Python requests

Generate a requests.request() call with method, URL, headers, Basic Auth and request data. JSON request bodies are emitted through the native JSON parameter.

cURL to JavaScript fetch

Create a browser or modern runtime fetch() request with method, headers and a string or JSON body.

cURL to Axios

Generate an Axios request configuration for Node.js or application code, including URL, method, headers, auth and request data.

cURL to PHP

Create PHP cURL setup code with curl_setopt_array(), HTTP headers, request method and request body.

Supported cURL options

This implementation focuses on common API request flags: -X/--request, -H/--header, -d/--data, --data-raw, --data-binary, --data-ascii, --json, -u/--user, -b/--cookie, -A/--user-agent, -e/--referer, -G/--get, --url, -I/--head, -L/--location and -s/--silent.

How curl --json is converted

curl added --json in version 7.82.0 as a shortcut for a binary request body plus default Content-Type: application/json and Accept: application/json headers. This converter follows those semantics for inline JSON. If you repeat --json, the fragments are concatenated without an ampersand before JSON parsing and code generation.

Explicit -H/--header values still win: if the source command already supplies Content-Type or Accept, the converter does not add a duplicate default. File/stdin forms such as --json @payload.json and --json @- are rejected because the browser cannot safely infer shell-local file or stdin contents from pasted command text.

What is intentionally not converted

A cURL command can also be a shell program. Pipes, redirects, shell variables, command substitution, local-file bodies such as @payload.json, --json file/stdin forms, multipart -F/--form, and uncommon cURL flags can change request semantics in ways that should not be guessed. This tool rejects those cases instead of silently producing code that may make a different request.

JSON body detection

When the request body parses as JSON and the request has an application/json content type, the generated Python and Axios examples use native JSON data structures and JavaScript uses JSON.stringify(). Other bodies are emitted as strings. A regular -d body without a content type is treated like cURL's common URL-encoded form behavior.

Security and privacy

The converter does not execute the cURL request and does not send the command to Smart Web Utility. Tokens, cookies and credentials remain in the browser during conversion, but generated code can still contain secrets from the source command. Remove real credentials before sharing generated snippets, screenshots or bug reports.

Conversion is a starting point, not a runtime guarantee

HTTP libraries differ in redirect behavior, TLS configuration, cookie handling, streaming, compression and environment-specific defaults. Review generated code before production use, especially when the original command relies on advanced cURL behavior or shell features.

Frequently asked questions

Can I convert cURL to Python requests?

Yes. Choose Python requests and the tool generates a requests.request() example from the supported cURL options.

Can I convert cURL to fetch or Axios?

Yes. JavaScript fetch and Node.js Axios are available from the Output selector.

Does the converter run the API request?

No. It only parses the command and generates code locally in the browser.

Why does the tool reject some valid cURL commands?

Complex shell syntax and advanced cURL options can require runtime context. Rejecting unsupported input is safer than generating code with different semantics.

Does it support Bearer tokens?

Yes. Bearer tokens supplied through an Authorization header are preserved as a normal HTTP header in generated code.

Does it support curl --json?

Yes for inline JSON. The converter applies curl's default JSON Content-Type and Accept headers unless the command overrides them. Repeated inline --json fragments are concatenated. Local-file and stdin forms remain intentionally unsupported.
