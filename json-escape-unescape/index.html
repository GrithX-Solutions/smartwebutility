Escape text for a JSON string

JSON strings use backslash escape sequences for characters that would otherwise terminate the string or represent control characters. The Escape action uses the browser's JSON serializer so quotation marks, backslashes, tabs, carriage returns, line feeds and other required control characters are encoded according to JSON rules.

Quotes and backslashes

Double quotes become \" and backslashes become \\, allowing the text to be placed safely inside a JSON string value.

Tabs and line breaks

Tabs, new lines and carriage returns become \t, \n and \r rather than literal control characters inside the escaped output.

Optional JSON quotes

Enable surrounding quotes when you need a complete JSON string literal. Leave it disabled when another application expects only the escaped string content.

Forward slashes

JSON does not require forward slashes to be escaped. The optional slash setting emits \/, which is useful when you specifically need to avoid a literal sequence such as </script> while embedding JSON text inside an HTML script element.

Unescape JSON string content

The Unescape action accepts either a complete quoted JSON string or raw escaped string content. It decodes valid JSON escapes such as \b, \f, \n, \r, \t, escaped quotes, escaped backslashes and \uXXXX Unicode sequences.

Escaping is not the same as formatting JSON

This tool operates on a single JSON string value. It does not beautify objects, validate object structure or repair malformed JSON documents. Use the JSON Formatter when your input is an object or array and you need structural validation, indentation or minification.

JSON escaping does not make text safe for every output context

JSON escaping answers one question: how should text be represented inside a JSON string value? It is not a general-purpose sanitizer. HTML, URLs, shell commands and SQL all have different parsing rules, so reusing JSON escapes in those contexts can still produce broken or unsafe output.

A common edge case is JSON embedded directly inside an HTML <script> element. A JSON string may legally contain the literal text </script>, which the HTML parser can treat as the end of the script element before JavaScript or JSON parsing occurs. Enabling “Escape / as \/” changes that sequence to <\/script>. Applications that inline untrusted JSON into HTML can require additional context-specific handling for characters such as <, > and &; follow the destination framework's safe serialization guidance rather than treating this string tool as an HTML sanitizer.

Unicode behavior

RFC 8259 allows ordinary Unicode characters directly inside JSON strings. The Escape action therefore keeps readable Unicode text such as accented letters and emoji instead of forcing every non-ASCII character into \uXXXX. Characters that JSON requires to be escaped—quotation marks, backslashes and control characters below U+0020—are encoded by the browser's JSON serializer.

Common developer use cases

JSON escaping is useful when placing arbitrary text inside API payload string fields, test fixtures, configuration values, logs or nested JSON strings. Unescaping is useful when reading copied log output, serialized message content or API fields that contain escaped string data. When the destination is source code, HTML, a URL, SQL or a shell command, use the escaping or parameterization rules for that destination rather than assuming JSON rules are interchangeable.

Privacy

Escaping and unescaping run locally in browser JavaScript. Input text is not submitted to a Smart Web Utility API for this operation.

Frequently asked questions

What does JSON escape do?

It converts characters that need special representation inside a JSON string into valid JSON escape sequences.

Can I unescape a quoted JSON string?

Yes. A valid quoted JSON string can be parsed directly, and raw escaped content is also accepted.

Are forward slashes required to be escaped?

No. Escaping / as \/ is optional in JSON. It is commonly useful when avoiding a literal </script> sequence in JSON embedded inside an HTML script element.

Does JSON escaping make text safe for HTML or SQL?

No. JSON, HTML, URLs, SQL and shell commands use different parsing rules. Use the destination context's encoder, sanitizer or parameterized API instead.

Does this validate a complete JSON object?

No. Use the JSON Formatter for objects and arrays.
