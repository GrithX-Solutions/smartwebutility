Convert Unix timestamps in seconds or milliseconds

A Unix timestamp identifies one instant as elapsed time from 00:00:00 UTC on January 1, 1970. Traditional Unix time uses seconds, while JavaScript and many APIs commonly use milliseconds. This converter accepts either unit and shows ISO 8601, UTC, browser-local time, Unix seconds and Unix milliseconds for the same instant.

Seconds

Select Seconds when your source stores classic epoch seconds, such as 1769438400.

Milliseconds

Select Milliseconds for JavaScript-style epoch values, which are typically much larger than second-based timestamps.

UTC and ISO 8601

Use the UTC and ISO outputs when you need a timezone-independent representation for logs, APIs or debugging.

Browser-local time

The local output uses the timezone configured in your browser, so the displayed clock time can differ between users.

How automatic seconds vs milliseconds detection works

Auto detect uses a simple numeric rule: an absolute value of 1,000,000,000,000 or more is treated as milliseconds; smaller values are treated as seconds. That rule handles most modern timestamps, but no bare number carries its unit. A millisecond value for an early date can therefore look like seconds. Choose Seconds or Milliseconds explicitly whenever the source API, database or log format documents the unit.

Date to Unix conversion uses your local timezone

The Date → Unix field uses your browser's local timezone because the input does not include a timezone offset. For example, entering 09:00 means 09:00 in the timezone configured on your device. The resulting Unix value still represents an absolute instant. If you need to convert a time stated in another timezone, convert that source time to your local equivalent first or use a timezone-aware workflow.

UTC, local time and Unix time describe the same instant differently

A Unix timestamp itself has no display timezone. The timestamp 0 represents the Unix epoch at 1970-01-01 00:00:00 UTC. Local rendering applies your browser's timezone offset to that instant, while ISO 8601 output uses a UTC Z suffix. Different local clock readings can therefore correspond to exactly the same Unix timestamp.

Can Unix timestamps represent dates before 1970?

Yes. Negative Unix timestamps represent instants before the Unix epoch when the underlying runtime supports the date. This converter passes the value through the browser's JavaScript Date implementation and reports an error if the resulting date falls outside its supported range.

What is the Unix 2038 problem?

The 2038 problem affects legacy systems that store epoch seconds in a signed 32-bit integer. That representation reaches its maximum value at 2,147,483,647 seconds and then overflows. It is a storage limitation in those systems, not a rule that Unix time itself stops working in 2038. Modern systems commonly use wider integer or date representations.

Frequently asked questions

Does the converter send timestamps to a server?

No. Timestamp parsing and formatting run in browser JavaScript on this page.

Should I use seconds or milliseconds?

Use the unit documented by the system that produced the value. Auto detection is convenient for common modern timestamps, but an explicit unit is more reliable when you know it.

Why does local time differ from UTC?

They display the same instant using different timezone rules. UTC has no local offset; the local result uses your browser's configured timezone.

Why did a timestamp produce the wrong year?

The most common cause is interpreting seconds as milliseconds or milliseconds as seconds. Select the correct unit manually and run the conversion again.
