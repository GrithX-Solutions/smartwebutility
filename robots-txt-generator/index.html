Build a robots.txt draft for crawler access rules

This generator creates one robots.txt user-agent group from the values you enter. Add a crawler name, one Allow or Disallow path per line, an optional crawl-delay value and an optional sitemap URL, then copy the generated text. Review the file before publishing it at your site's /robots.txt location.

What the generator writes

User-agent

Choose which crawler group receives the rules. If you leave the field empty, the generator uses * for all crawlers.

Disallow

Add paths that compliant crawlers should not fetch for that user-agent group. The generator writes one Disallow line for each non-empty entry.

Allow

Add more specific paths that should remain crawlable when they sit inside a broader blocked path. Support and matching behavior depend on the crawler.

Sitemap

Add a fully qualified sitemap URL so supporting crawlers can discover the sitemap location from robots.txt.

robots.txt controls crawling, not access or guaranteed indexing

A robots.txt rule asks compliant crawlers whether they may fetch a URL. It is not authentication, and the file itself is public. Do not use it to protect private files. A blocked URL can also remain discoverable or appear in search results without its content being crawled, so use the appropriate indexing or access-control mechanism for your actual goal.

Be careful with Crawl-delay

The generator can write a Crawl-delay line because some crawlers support it, but support is not universal. Google documents that its crawlers do not process crawl-delay. Check the documentation for each crawler you target instead of assuming one delay directive works everywhere.

The generator does not validate rule precedence

This page assembles the text you provide; it does not simulate crawler matching, validate every path pattern or test the live file. Use the Robots.txt Tester to evaluate rules for a specific crawler and URL, then verify the deployed file from the public site root.

Use a complete URL for the Sitemap directive

For Google, the Sitemap value must be a fully qualified URL that includes the protocol and host. A robots.txt file can contain multiple sitemap lines, but the current generator provides one sitemap field. Add additional lines manually when your site publishes more than one sitemap or sitemap index.

Safer robots.txt workflow

Draft narrowly

Block only the paths you intend to restrict from crawling. A broad slash rule can affect an entire site.

Test important URLs

Check representative allowed and disallowed paths before replacing a production robots.txt file.

Deploy at the site root

Publish the reviewed file as /robots.txt on the correct host and protocol.

Verify after release

Fetch the public file and confirm that a CMS, CDN or deployment step did not rewrite the intended rules.

Frequently asked questions

Can robots.txt keep a private page secret?

No. Use authentication or another access-control mechanism for private content. robots.txt is a public crawler-control file.

Does Google support Crawl-delay in robots.txt?

No. Google's current robots.txt documentation lists crawl-delay as unsupported. Other crawler operators can implement different rules.

Does this generator test the rules?

No. It builds the text. Use the Robots.txt Tester and verify the deployed file before relying on the rules.
