Build a robots.txt draft for crawler access rules

This generator creates one robots.txt rule group from the values you enter. Add one or more crawler tokens, one Allow or Disallow path per line, an optional crawl-delay value and one or more sitemap URLs, then copy the generated text. Repeated User-agent lines apply the same group of rules to multiple crawlers, which Google explicitly supports. Review the file before publishing it at your site's /robots.txt location.

What the generator writes

User-agent

Enter one crawler token per line. The generator emits consecutive User-agent lines so the same group applies to every listed crawler. If you leave the field empty, it uses *.

Disallow

Add paths that compliant crawlers should not fetch for that user-agent group. The generator writes one Disallow line for each non-empty entry.

Allow

Add more specific paths that should remain crawlable when they sit inside a broader blocked path. Support and matching behavior depend on the crawler.

Sitemap

Add one fully qualified HTTP(S) sitemap or sitemap-index URL per line. Google supports multiple Sitemap fields and does not tie them to one user-agent group.

robots.txt controls crawling, not access or guaranteed indexing

A robots.txt rule asks compliant crawlers whether they may fetch a URL. It is not authentication, and the file itself is public. Do not use it to protect private files. A blocked URL can also remain discoverable or appear in search results without its content being crawled, so use the appropriate indexing or access-control mechanism for your actual goal.

Be careful with Crawl-delay

The generator can write a Crawl-delay line because some crawlers support it, but support is not universal. Google documents that its crawlers do not process crawl-delay. Check the documentation for each crawler you target instead of assuming one delay directive works everywhere.

What the inline validation does — and does not do

The generator rejects Allow/Disallow entries that do not begin with /, rejects sitemap values that are not absolute HTTP(S) URLs and rejects non-numeric crawl-delay values. It does not simulate rule precedence, wildcard matching or a specific crawler's live behavior. Use the Robots.txt Tester to evaluate rules for a crawler and URL, then verify the deployed file from the public site root.

Use complete URLs for Sitemap directives

For Google, each Sitemap value must be a fully qualified URL that includes the protocol and host. A robots.txt file can contain multiple sitemap lines, and Google states there is no limit on the number of sitemap fields. This generator accepts one sitemap URL per line and writes each as a separate directive.

Safer robots.txt workflow

Draft narrowly

Block only the paths you intend to restrict from crawling. A broad slash rule can affect an entire site.

Test important URLs

Check representative allowed and disallowed paths before replacing a production robots.txt file.

Deploy at the site root

Publish the reviewed file as /robots.txt on the correct host and protocol.

Verify after release

Fetch the public file and confirm that a CMS, CDN or deployment step did not rewrite the intended rules.

Frequently asked questions

Can robots.txt keep a private page secret?

No. Use authentication or another access-control mechanism for private content. robots.txt is a public crawler-control file.

Does Google support Crawl-delay in robots.txt?

No. Google's current robots.txt documentation lists crawl-delay as unsupported. Other crawler operators can implement different rules.

Can one rule group target several crawlers?

Yes. Add one user-agent token per line. The generator writes consecutive User-agent lines followed by the shared Allow/Disallow rules, matching Google's documented grouping syntax.

Can I add more than one sitemap?

Yes. Add one fully qualified HTTP(S) sitemap or sitemap-index URL per line. Each one becomes its own Sitemap directive.

Does this generator test the rules?

No. It validates basic input shape and builds the text. Use the Robots.txt Tester and verify the deployed file before relying on the rules.
