Create a robots.txt file

Robots.txt provides crawl directives to compliant bots. It is not an access-control mechanism and should not be used to protect sensitive content.

Build a robots.txt file for crawl control

A robots.txt file tells compliant crawlers which URL paths they may request on a specific host, protocol and port. It belongs at the site root, for example https://example.com/robots.txt. Use this generator to create a small starter file and then review every rule before deploying it.

Crawling and indexing are different

A robots.txt Disallow rule controls crawling; it is not a reliable way to remove a URL from search results. A blocked URL can still be known from links or other signals. When a page must not be indexed, use an appropriate indexing directive on a crawlable response and verify the result with the search engine's own inspection tools.

User-agent groups

Group rules under the crawler name they apply to. User-agent: * is the general group for compliant crawlers that do not have a more specific rule.

Allow and Disallow

Keep path rules as narrow as possible. Blocking CSS, JavaScript or other resources required to understand a page can make rendering and diagnosis harder.

Sitemap directive

Add an absolute sitemap URL when you want crawlers to discover the site's sitemap location directly from robots.txt.

Validate after upload

Fetch the production robots.txt file after deployment and confirm that it returns HTTP 200 with the exact rules you intended.

Avoid unsupported assumptions

Not every crawler implements every non-standard directive. Google documents support for user-agent, allow, disallow and sitemap, while directives such as crawl-delay are not part of Google's supported robots fields. Keep the file standards-based and use server controls when you need real access control.
