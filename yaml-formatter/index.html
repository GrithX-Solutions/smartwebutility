Format and validate YAML documents in your browser

This YAML Formatter parses the input with js-yaml 4.1.0 and serializes each parsed document back to clean YAML using either 2-space or 4-space indentation. Parsing and formatting happen in browser JavaScript, while the parser library itself is loaded from jsDelivr.

What happens when you format YAML

Syntax validation

The tool parses the complete YAML stream before producing output. A parser error is shown instead of returning formatted text when any document is invalid.

2 or 4 spaces

Choose the indentation width for the serialized output. The formatter uses spaces rather than tabs for YAML indentation.

Local file input

Open a local YAML file up to 5 MB or paste text directly into the editor. File contents are read by the browser.

Copy or download

Copy the formatted result or download it as formatted.yaml after validation succeeds.

Formatting can change YAML presentation

This tool performs a parse-and-dump cycle rather than adjusting whitespace in the original source text. The output can therefore normalize quoting, flow style and other presentation details while preserving the parsed data value. Review configuration files before committing them when formatting style itself carries team or tooling expectations.

Comments are not preserved

The current parser loads YAML into a JavaScript value and then serializes that value again. Comments are not part of the parsed data value, so the formatter can remove them. Do not run a comment-heavy configuration through this tool unless you have the original file available and are comfortable restoring important documentation comments.

Anchors, aliases and references may be rewritten

YAML anchors and aliases describe relationships in the source document, but the formatter emits output with reference generation disabled. A parse-and-dump cycle can expand or rewrite those source-level constructs. If anchors and aliases are important to maintain as authored, use an editor or formatter designed to preserve YAML source structure.

Multi-document YAML streams keep explicit document boundaries

The formatter uses js-yaml's multi-document parser. When input contains two or more YAML documents, each parsed document is serialized independently and the output prefixes every document with ---. That keeps the stream boundaries visible instead of merging documents into one data structure. A single-document input keeps the simpler single-document output without an added marker.

Formatting remains a parse-and-dump operation for each document. Comments and exact source presentation can still change, and aliases or anchors can be rewritten inside their document. YAML anchors cannot reference nodes in another document, so each stream document remains an independent serialization unit.

Frequently asked questions

Does the formatter preserve YAML comments?

No. It parses YAML into data and serializes the value again, so source comments can be removed.

Does Smart Web Utility upload my YAML for formatting?

No. The YAML value is parsed in browser JavaScript. The page separately loads the js-yaml library from a CDN.

Can I use four-space indentation?

Yes. Choose 2 or 4 spaces before formatting.

Can I format multiple YAML documents in one stream?

Yes. Separate documents with YAML document markers such as ---. The formatter validates the whole stream and emits each formatted document with an explicit --- boundary.
