Generate random port numbers for TCP or UDP configurations

A transport port is a 16-bit number, so the numeric space runs from 0 through 65535. This generator intentionally uses ports 1 through 65535 and provides presets for common non-system ranges. The number itself is not inherently “TCP” or “UDP”; the transport protocol is determined by the service that uses it.

Dynamic/private range

The 49152–65535 range is commonly designated for dynamic or private use. It is the default here because it avoids the lower system and user/registered ranges.

User/registered range

The 1024–49151 range contains many registered service assignments. Use it only when your application or test environment allows the selected value and you have checked for conflicts.

Non-system range

The 1024–65535 preset excludes the well-known system range while allowing both user/registered and dynamic/private numbers.

Custom range

Choose any minimum and maximum between 1 and 65535. Unique mode prevents duplicate numbers within one generated batch when the requested count fits inside the range.

A random port is not automatically available

This tool generates numbers only. It does not inspect your computer, container, router, firewall, Kubernetes cluster, remote server or operating-system socket table. A generated port can already be bound by another process, reserved by an application, blocked by policy or unsuitable for the environment where you plan to use it.

Check availability on the target system

Before binding a service, verify the chosen port on the machine or runtime that will actually listen. Port availability can differ between hosts, network namespaces, containers and protocols. A TCP listener and a UDP listener also use separate transport namespaces, so a numeric port can have different occupancy depending on protocol.

Why port 0 is excluded

Port 0 has special meaning in many socket APIs: asking the operating system to bind port 0 commonly means “choose an available ephemeral port for me.” Because this page returns explicit numbers intended for configuration or fixtures, it starts at port 1 rather than generating 0.

Unique random ports for fixtures and tests

Unique mode is useful when you need several distinct numeric values in a fixture, configuration sample or test dataset. It guarantees uniqueness only inside the generated batch. It does not guarantee that those ports are unused on a real machine or that another process will not claim them later.

Cryptographic randomness is not port security

The browser Web Crypto API provides an unbiased random source for selecting numbers, but hiding or randomizing a port does not replace authentication, authorization, firewall rules or secure service configuration. Network services should be protected based on their actual threat model.

Frequently asked questions

What is the valid port number range?

Transport port numbers are 16-bit values from 0 through 65535. This generator returns explicit nonzero values from 1 through 65535.

What range does the random port generator use by default?

The default is the dynamic/private range from 49152 through 65535.

Does this check whether a port is open or free?

No. It only generates random numbers. Availability must be checked on the target system.

Can it generate unique port numbers?

Yes. Unique mode prevents duplicates within the current generated batch when the selected range is large enough.

Are generated ports sent to the server?

No. Generation runs locally in browser JavaScript.
