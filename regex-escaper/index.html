Escape literal text for a regular expression

Regular-expression syntax gives special meaning to characters such as dots, parentheses, square brackets, plus signs and question marks. When a user-entered string is supposed to match literally, those characters must be escaped before the text is inserted into a JavaScript RegExp pattern.

Regex syntax characters

Characters including ^ $ \ . * + ? ( ) [ ] { } | / are emitted in escaped form so they are treated as literal characters instead of assertions, quantifiers, groups, character classes or delimiters.

Leading letters and digits

Modern RegExp.escape() hex-escapes an initial ASCII letter or digit. This prevents the escaped text from accidentally extending a preceding backreference or hexadecimal/control escape when it is embedded in a larger pattern.

Other punctuation

Punctuation such as hyphen, comma, equals sign and quotes can require hexadecimal escapes because blindly prefixing every punctuation character with a backslash is not valid in every Unicode-aware regex context.

Whitespace and line breaks

Tabs, newlines, carriage returns and other relevant whitespace are represented with stable escape sequences so the result can be inserted into regex source without introducing an accidental line break.

Common JavaScript regex characters and escape output

For quick reference, common regex operators become literal matches when escaped. Modern RegExp.escape() also uses hexadecimal escapes where a simple backslash would be ambiguous or invalid.

  • . becomes \. so it matches a literal period instead of any character.
  • / becomes \/ so it can appear safely inside a JavaScript regex literal.
  • \ becomes \\ so the pattern matches a literal backslash.
  • (, ), [, ], { and } receive backslash escapes so they lose grouping, class or quantifier meaning.
  • - becomes \x2d under RegExp.escape() because \- is not valid in every Unicode-aware context.
  • An initial ASCII letter or digit uses \xNN; for example, an initial a becomes \x61 so it cannot extend a preceding escape sequence.

Why a simple replace is not always enough

A common helper only backslash-escapes the traditional metacharacters. That works for many standalone patterns, but modern ECMAScript escaping handles additional edge cases: a leading alphanumeric character, punctuation that cannot safely use identity escapes under Unicode modes, slash delimiters, non-ASCII whitespace and lone surrogate code units. These rules follow the current ECMAScript RegExp.escape() specification; MDN also documents the API as broadly available in current browsers since May 2025.

Escaped pattern output

The default output is pattern text suitable for use as literal content inside a JavaScript regular expression. For example, a dot in a domain name becomes an escaped dot instead of the wildcard operator. The output is regex source, not a JavaScript string literal, so it may contain backslashes exactly as the regex parser should see them.

RegExp constructor output

Constructor mode wraps the escaped pattern in new RegExp(...) and quotes the pattern as a JavaScript string. This adds the extra string-literal escaping needed by source code, which is different from escaping the regular expression pattern itself.

Regex literal output

Literal mode produces JavaScript syntax such as /escaped/u. Slash characters are escaped so they do not terminate the literal. The flags field is validated by the browser before output is produced, which helps catch duplicate or unsupported flag combinations.

JavaScript versus Python, .NET and other regex engines

Regular-expression engines share many metacharacters but do not have identical escaping APIs or Unicode rules. This tool follows JavaScript/ECMAScript RegExp.escape() semantics. Python's re.escape(), .NET's Regex.Escape(), PCRE and other engines can produce different escaped text for the same input.

Escaping does not make a regex safe from every performance problem

Escaping literal user text prevents that text from introducing regex operators, but the surrounding pattern can still be expensive or vulnerable to excessive backtracking. Review the complete regular expression and use bounded inputs where performance matters.

Frequently asked questions

Which regex characters does this escape?

It follows JavaScript RegExp.escape() rules, including regex syntax characters, slash delimiters, leading alphanumeric protection, selected punctuation and whitespace escapes.

Why does the first letter sometimes become \xNN?

That protects the escaped fragment when it follows another escape sequence inside a larger regex pattern.

Is regex escaping the same as JavaScript string escaping?

No. Regex source escaping and JavaScript string-literal escaping happen at different parsing layers. Constructor output handles both layers for you.

Can I use the output in Python or .NET?

The literal may work in simple cases, but this tool specifically follows ECMAScript rules. Use the target language's escaping API when exact engine compatibility is required.

Is input uploaded?

No. Escaping runs locally in browser JavaScript.
