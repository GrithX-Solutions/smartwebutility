Generate ULIDs with the canonical 26-character format

A ULID is a 128-bit identifier split into a 48-bit Unix timestamp in milliseconds and an 80-bit random component. Its canonical string uses 26 Crockford Base32 characters, so it is shorter than the familiar hyphenated UUID text form while remaining case-insensitive and URL-safe.

Time-sortable prefix

The first 10 characters encode the 48-bit millisecond timestamp. That makes ordinary ULID strings sort by time when compared lexicographically.

80 random bits

The final 16 characters encode 80 bits of randomness. This generator uses the browser Web Crypto API for the random component.

Monotonic mode

When the current automatic timestamp does not advance, monotonic mode keeps the previous logical timestamp and increments the 80-bit random component so later values remain lexicographically increasing.

Crockford Base32 alphabet

ULID uses the alphabet 0123456789ABCDEFGHJKMNPQRSTVWXYZ. The letters I, L, O and U are excluded. Canonical ULIDs are commonly displayed in uppercase, though comparison is case-insensitive according to the specification.

ULID timestamp range

The timestamp field is 48 bits wide and stores Unix time in milliseconds. Because 48 bits are encoded into 10 Base32 characters, valid canonical ULIDs use only the portion of that 50-bit text space that fits the 48-bit timestamp. This generator rejects custom times outside the supported range instead of wrapping them silently.

Why use monotonic ULIDs?

Standard random ULIDs created in the same millisecond share the same timestamp prefix but their random suffixes can sort in any order. Monotonic mode increments the previous random suffix when the timestamp has not advanced. In automatic-time mode, if the browser clock moves backward, the generator keeps the previous logical timestamp and continues incrementing so it does not emit a lexicographically older ULID. When time moves forward, it seeds fresh Web Crypto randomness for the new millisecond.

Changing the custom timestamp or toggling monotonic mode starts a new local monotonic sequence. This page does not coordinate state across tabs, browsers, devices or application processes.

ULID versus UUID v4 and UUID v7

UUID v4 is primarily random and does not contain creation time. UUID v7 also carries a Unix-millisecond timestamp and can provide time-oriented ordering while retaining the UUID layout and ecosystem. ULID uses a different Base32 text representation and devotes 80 bits to its random component. Use the identifier format required by your database, API or application contract.

Custom timestamp generation

Enable the custom timestamp option when you need deterministic time prefixes for testing, migrations or fixtures. The random component remains newly generated unless monotonic mode needs to increment a previous value created with the same timestamp.

Decode and validate an existing ULID

The inspector accepts the canonical 26-character Crockford Base32 representation case-insensitively, normalizes it to uppercase, and rejects characters outside the ULID alphabet. It also rejects values whose encoded timestamp exceeds the 48-bit ULID limit. A valid result exposes the timestamp in milliseconds and UTC plus the 16-character, 80-bit randomness component in Base32 and hexadecimal form.

Timestamp decoding is not authentication

The visible time prefix is metadata, not proof that an event actually happened at that moment. A user can generate a ULID with an arbitrary supported timestamp. Do not use ULID timestamps as trusted audit evidence without an independent trusted source.

Frequently asked questions

How long is a ULID?

A canonical ULID is 26 Crockford Base32 characters.

Is a ULID sortable?

Yes. The timestamp occupies the leading characters, so ULIDs sort by timestamp lexicographically. Monotonic mode also preserves local generation order when the automatic clock repeats or moves backward.

What happens if the browser clock moves backward?

In automatic-time monotonic mode, the generator keeps the last logical timestamp and increments the previous random component until the real clock moves forward again. Separate tabs or processes do not share that state.

Can I generate ULIDs for a custom date?

Yes. Enable the custom timestamp option and choose a supported date and time.

Does a ULID contain randomness?

Yes. The lower 80 bits are the randomness component.

Can I decode an existing ULID?

Yes. Paste a 26-character ULID into the inspector to validate it and read its embedded millisecond timestamp plus the 80-bit randomness component.

Are lowercase ULIDs valid?

Yes. The ULID specification treats the encoded form as case-insensitive. The inspector accepts lowercase input and normalizes valid values to uppercase.

Are generated ULIDs uploaded?

No. Generation and timestamp decoding run locally in browser JavaScript.
