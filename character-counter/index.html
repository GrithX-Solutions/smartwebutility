Character count depends on what “character” means

Plain ASCII text makes most counters look identical. Emoji, combining marks and supplementary Unicode characters expose the difference. This Character Counter therefore shows four separate measurements instead of hiding them behind one ambiguous number.

Visible characters

This is the user-perceived grapheme count. Modern browsers use Intl.Segmenter with grapheme boundaries, so a joined emoji or a letter plus combining mark can count as one visible character. Older browsers fall back to Unicode code points.

Unicode code points

Code points are counted with JavaScript iteration over the string. A supplementary emoji is one code point even though it uses two UTF-16 units. A combined visible symbol can still contain multiple code points.

UTF-16 units

This is JavaScript String.length. It is also the unit used by HTML maxlength. A non-BMP character such as many emoji therefore contributes two UTF-16 units.

UTF-8 bytes

This is the encoded byte length from TextEncoder. It matters when an API, database, storage field or protocol limit is defined in bytes rather than characters.

With whitespace and without whitespace

The primary visible-character count includes spaces, tabs and line breaks. The Without whitespace value removes JavaScript Unicode whitespace first and then counts the remaining visible graphemes. That is broader than removing only ordinary ASCII spaces, so the label is intentionally “without whitespace.”

Track a limit using the correct counting model

Enter an optional limit and choose whether that limit applies to visible characters, UTF-16 units, Unicode code points or UTF-8 bytes. The progress indicator shows how many units remain or how far the text is over. This is useful for forms, APIs and storage rules that publish an explicit numeric limit.

No single setting can reproduce every social network, messaging service or custom application. Platforms can apply their own normalization, URL handling or weighted-count rules, so their live counter remains the final authority for platform-specific limits.

Unicode examples that change the count

Emoji

A single emoji can use a surrogate pair in UTF-16. Emoji with skin-tone modifiers or zero-width joiners can contain multiple code points while still appearing as one grapheme.

Combining marks

A visible accented letter can be stored as a base letter plus a combining mark. The grapheme count can be one while the code-point and UTF-16 counts are two.

Flags

Many flag emoji are formed from two regional-indicator code points. A grapheme-aware counter can report one visible flag while code-point and UTF-16 totals remain higher.

Bytes

ASCII usually uses one UTF-8 byte per character. Many accented characters, symbols and emoji require multiple bytes, so byte limits can be reached before a visible-character limit.

What the standards say

MDN documents that JavaScript strings are sequences of UTF-16 code units and that String.length reports those units. MDN also documents Intl.Segmenter for grapheme segmentation and the HTML maxlength attribute as a UTF-16-unit limit. These definitions are why this tool shows the models separately rather than declaring one universal “correct” character count.

Frequently asked character-count questions

Why does an emoji sometimes count as two characters?

Many emoji use a Unicode code point outside the Basic Multilingual Plane, which takes two UTF-16 code units. JavaScript String.length therefore returns two for that code point even though a reader sees one symbol.

What is a grapheme cluster?

A grapheme cluster is a user-perceived character. One grapheme can contain multiple Unicode code points, such as a base letter plus a combining accent or a joined emoji sequence.

Which count matches HTML maxlength?

HTML maxlength is measured in UTF-16 code units, so use the UTF-16 figure when checking a native HTML input or textarea maxlength rule.

Does “without whitespace” remove tabs and line breaks?

Yes. This tool removes JavaScript whitespace, including ordinary spaces, tabs and line breaks, before counting the remaining visible graphemes.

Does the tool upload my text?

No. The counting logic runs locally in your browser.
