Create starter Schema.org JSON-LD

Use this Schema Markup Generator and JSON-LD generator to create type-specific markup for Organization, WebSite, SoftwareApplication, Article and LocalBusiness. The form changes by type so a LocalBusiness can include a real postal address, an Article can include author and dates, and a SoftwareApplication can include its offer and genuine aggregate rating instead of forcing every entity into the same generic field set.

Organization

Describe a real organization with name, URL, description, logo, telephone and sameAs profiles when applicable. Google's Organization documentation has no required properties, so accuracy and entity consistency matter more than filling every field.

WebSite

Describe the website entity with its stable public name, URL and optional alternate name. Do not use WebSite as a substitute for the more specific entity that the page itself represents.

SoftwareApplication

Add app category, operating system and an Offer. Google's current software-app rich-result documentation requires name, offers.price and either a genuine rating or review; this generator can flag those gaps but will never invent review data.

Article and LocalBusiness

Article output can include author, publication/modification dates and image. LocalBusiness output can include the required name/address combination plus telephone and price range. Google recommends using the most specific LocalBusiness subtype in production when one accurately applies.

Schema.org validity and Google feature readiness are different

Schema.org defines a broad vocabulary, while Google supports specific search features with its own required and recommended properties. The readiness panel uses conservative checks for the fields this tool can verify locally; it does not claim that generated markup is automatically eligible for a rich result. Always validate the final production markup and page content.

Match structured data to visible page content

Generated properties should accurately describe the entity and content users can actually see or verify on the page. Do not add fake reviews, prices, addresses, authors, dates or other values just to populate a schema field. Misleading markup can make structured data ineligible for search features.

Deployment workflow

1. Generate

Choose the closest entity type and fill only fields that are true for the page.

2. Extend

Add the required type-specific properties from Schema.org and the current documentation for the search feature you want to support.

3. Validate

Test the final production markup with Google's Rich Results Test when the type is supported there, and use a Schema.org validator for vocabulary-level checks.

4. Inspect after deployment

Use URL Inspection to confirm the rendered page exposes the markup you intended and is crawlable.

Schema.org validation vs Google rich-result eligibility

A Schema.org validator and Google's Rich Results Test answer different questions. Vocabulary-level validation helps confirm that properties and types make sense in Schema.org. Google's Rich Results Test checks markup for search features that Google currently supports and can flag missing required or recommended properties for those features. Passing either test does not guarantee that a rich result will appear.

Choose the structured data type that matches the real entity

Organization schema

Use Organization when the page or site is establishing the identity of a company, nonprofit or other organization. Keep names, URLs, logos and contact details consistent with visible public information.

WebSite schema

Use WebSite for the website entity itself. It is different from an individual WebPage and should represent the stable site-level identity.

SoftwareApplication schema

Use SoftwareApplication when the page describes real software or an app. Add the production properties that accurately describe the application rather than inventing ratings, prices or platform details.

Article and LocalBusiness schema

Article and LocalBusiness usually need more type-specific properties than a generic starter form can safely infer. Extend the generated JSON-LD with values that are actually present and verifiable on the page.

Structured data publishing checklist

Generate the JSON-LD, extend it with the properties required for your real use case, validate the final markup, publish it on a crawlable page, and inspect the rendered page after deployment. Structured data should describe visible content accurately; it is not a substitute for useful page content, crawlability, canonicalization or normal on-page SEO.

Frequently asked schema markup questions

Does valid Schema.org markup guarantee a Google rich result?

No. Eligibility depends on whether Google supports that feature, whether required properties and guidelines are met, and whether Google chooses to show the enhancement.

Can I put several schema entities on one page?

Yes when they describe real entities and relationships on the page. More markup is not automatically better; model only what is accurate and useful.

Does the readiness message mean Google will show a rich result?

No. It only checks selected fields against current documented requirements or strong recommendations for the chosen type. Eligibility also depends on Google support, page content, technical guidelines, crawlability and Google's decision to display the feature.

Does the generator send my data anywhere?

No. The JSON-LD is assembled locally in browser JavaScript.
