Convert record-style XML into spreadsheet-ready CSV

This converter turns record-style XML into a comma-separated table in your browser. It is most useful when one XML root contains repeated records such as users, products, orders or log entries. The tool creates one header row, one CSV row per detected record and a shared set of columns from the fields it finds.

How this XML to CSV converter chooses rows

The converter inspects the direct child elements under the XML document root. When one child tag repeats, it uses the most frequent repeated tag as the record type and converts each matching element into a CSV row. If no direct child tag repeats, it treats the root's direct child elements as rows. This rule is predictable, but it will not automatically discover a repeating list buried several wrapper levels deeper.

Nested elements

Nested child names become dotted column paths. A value inside address.city stays distinguishable from another city elsewhere in the record.

XML attributes

Attributes become columns with an @ marker. For example, <user id="7"> produces an @id column.

Repeated nested fields

Repeated child elements inside one record receive indexed paths such as tag[0] and tag[1] instead of being silently discarded.

Mixed text

When an element contains both direct text and child elements, the direct text can appear in a #text path so it remains visible in the flattened result.

How CSV columns and escaping work

The converter builds the header from every flattened field found across the detected records. If one row does not contain a field that appears in another row, that cell stays empty. Output uses a comma delimiter and always includes the header row. Fields containing commas, double quotes or line breaks are wrapped in quotes, and embedded double quotes are doubled so spreadsheet software can read the value correctly.

Example: attributes and nested XML

For XML such as <users><user id="1"><name>Ada</name><contact><city>London</city></contact></user>...</users>, each user becomes a row. Typical columns include @id, name and contact.city. Use the Example button above to see the converter's actual mapping before you use your own file.

When XML does not map cleanly to CSV

XML can represent trees, several independent lists, namespaces and mixed content, while CSV represents a flat table. This converter does not apply an XSD, choose a custom XPath or let you select a different record path. If your records sit inside several wrapper levels, or one document contains multiple unrelated repeating collections, convert the relevant XML fragment separately or use XML to JSON when preserving hierarchy matters more than producing a table.

Browser privacy and file limit

Parsing, flattening and CSV generation run in browser JavaScript. Pasted XML and selected files are not sent to a Smart Web Utility conversion API. The file picker accepts XML files up to 5 MB; larger files are rejected before conversion. Remove secrets before sharing copied output or downloaded files with other people.

Frequently asked questions

Does this XML to CSV converter upload my file?

No. The page reads the selected XML file and performs conversion in your browser.

Which XML elements become CSV rows?

The converter looks at direct children of the document root and chooses the most frequent repeated tag. When no direct child tag repeats, it treats the direct root children as rows.

How are XML attributes represented?

Attributes use @ in generated column names. Nested attributes keep their parent path so their source remains clear.

Can I choose a semicolon, tab or pipe delimiter?

Not in the current converter. It produces comma-separated output with a header row. Use another transformation step if your downstream system requires a different delimiter.

Can every XML document become a useful CSV table?

No. Deeply hierarchical, mixed-content or multi-list XML may need a custom transformation because a flat CSV table cannot preserve every XML relationship.
