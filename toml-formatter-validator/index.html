Format and validate TOML in one step

This TOML formatter parses the document first and only produces formatted output when the syntax is valid. It is useful for configuration files such as Cargo.toml, pyproject.toml and other application settings that use Tom's Obvious, Minimal Language.

TOML syntax validation

Detect malformed keys, values, arrays, tables, dates and other syntax that cannot be parsed as a valid TOML document.

Consistent formatting

Valid TOML is parsed and serialized again so spacing, arrays, values and table layout use a consistent representation.

Local file workflow

Open a local .toml file up to 5 MB. The file text is read by your browser and is not uploaded for this workflow.

What the TOML validator checks

Validation is parser-based rather than a simple bracket or regex check. The page uses a TOML v1.1-compatible parser to read keys, dotted keys, tables, arrays, inline tables, booleans, numbers, strings and TOML date/time values. Invalid syntax is reported instead of generating output.

Formatting can normalize representation

A parser-and-serializer formatter does not preserve the source file byte-for-byte. Comments are not retained, whitespace is regenerated, and equivalent numeric or date representations can be normalized. If comments or exact lexical formatting are part of your workflow, keep the original file in version control and review the formatted output before replacing it.

Cargo.toml and pyproject.toml

TOML is commonly used by Rust projects in Cargo.toml and by Python tooling in pyproject.toml. This page validates TOML syntax only; it does not verify Cargo package rules, Python build-system metadata, dependency availability or application-specific schemas.

Large integers and safer key handling

The parser is configured to preserve integers beyond JavaScript's safe-number range when needed and to reject potentially unsafe object keys. That keeps formatting focused on TOML syntax without silently accepting values that could be represented incorrectly in ordinary JavaScript numbers.

Frequently asked questions

Does this validate TOML syntax?

Yes. The formatter parses the input as TOML and reports a parser error when the document is invalid.

Does formatting preserve comments?

No. The document is parsed into data and serialized again, so comments and exact source formatting are not retained.

Can I format Cargo.toml or pyproject.toml?

Yes, as TOML documents. The tool does not validate Cargo- or Python-specific metadata rules.

Is TOML uploaded to the server?

No. Parsing and formatting run in browser JavaScript on this page.

Which TOML syntax does the parser support?

The implementation uses a TOML v1.1-compatible parser and serializer.
