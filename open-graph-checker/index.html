What the Open Graph protocol actually requires

Open Graph uses metadata in the HTML <head>. Its core properties identify the shared object: title, type, image and canonical object URL. Other properties such as og:description, og:locale and og:site_name add context but are not part of that four-property core. Structured image properties can describe a secure URL, MIME type, width, height and alternative text.

If a page declares og:image, the protocol says it should also provide og:image:alt. This checker flags the missing alt value but does not invent a universal image-size score. Social platforms control their own card layouts, cropping and file-handling rules.

Why a correct live report can still differ from a shared card

Platforms can cache older metadata, crop images differently, apply their own fallbacks or use a previously scraped version of the URL. A live check proves what this request received now; it does not prove that Facebook, LinkedIn, Slack, Discord, WhatsApp or another service has refreshed its cache.

JavaScript can also change metadata after the initial response. Many link crawlers do not render a full application before extracting social metadata, so server-rendered head tags are the safer implementation. This checker intentionally evaluates the fetched HTML response rather than a post-JavaScript DOM.

Checker vs Open Graph Preview

Use this page for a deployed public URL: checker, tester, validator and debugger intent all belong here. Use the findings as diagnostics, not platform guarantees

A missing required property, malformed absolute URL, failed image response or non-image content type is a concrete implementation problem worth fixing. A clean report still cannot guarantee a specific social-card layout because each consumer can apply its own cache and rendering rules. For broader search metadata, canonical and robots checks, use the Meta Tag Checker.

Open Graph specification

The Open Graph protocol is the source of truth for required properties, optional metadata, image structure and array ordering. The checker follows that protocol rather than hard-coding unsupported universal title, description or image-size requirements.

Frequently asked Open Graph checker questions

Which Open Graph tags are required?

The protocol lists four required properties: og:title, og:type, og:image and og:url. A description and site name can be useful, but they are optional in the protocol.

Why does my OG image still not appear after this checker finds it?

The destination platform may have cached an older scrape, may reject the image for its own policy or rendering rules, or may not have refreshed the URL yet. Confirm the live image response here, then use the destination platform's current debugging or re-scrape workflow when available.

Does the checker run JavaScript before reading tags?

No. It reads the HTML returned by the server after safe redirects. That makes the report useful for catching metadata that exists only after client-side rendering and may be invisible to non-rendering link crawlers.

Can a page have more than one og:image?

Yes. Open Graph supports repeated values, and the protocol says the first tag receives preference during conflicts. This report shows all values while validating the first image as the primary candidate.

Does Open Graph improve Google rankings directly?

Do not treat Open Graph tags as a direct Google ranking requirement. They primarily describe shared objects for social and messaging previews. Keep search titles, canonicalization, visible content and indexing controls accurate for search separately.
