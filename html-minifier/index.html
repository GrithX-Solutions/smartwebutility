Minify HTML without uploading the document

This HTML minifier compresses source markup in browser JavaScript. Its conservative default profile removes ordinary comments, collapses unnecessary whitespace and removes redundant HTML attributes while avoiding more aggressive transformations unless you explicitly enable them.

Whitespace compression

Indentation and repeated whitespace can often be reduced without changing how normal HTML content is interpreted. Conservative collapse is used to avoid stripping every possible text boundary aggressively.

Comment removal

Regular HTML comments can be removed to save bytes. Conditional or tool-specific comments can matter in legacy workflows, so review output when your document depends on unusual comment syntax.

Redundant attributes

Some attributes have defaults that HTML already implies. The minifier can remove recognized redundant forms while leaving application-specific data attributes intact.

Exact byte savings

The tool reports input bytes, output bytes and percentage saved so you can measure whether a transformation is worth using rather than assuming every file benefits equally.

Why aggressive options are disabled by default

HTML minification is not merely deleting spaces. Removing optional tags, stripping quotes that HTML syntax permits you to omit, sorting attributes, or rewriting inline CSS and JavaScript can create larger interoperability or debugging changes than basic whitespace compression. Those controls are available, but they are opt-in so a first run remains conservative.

Attribute quotes can be optional in HTML but still matter to downstream parsers

The “Remove eligible attribute quotes” option asks the minifier to unquote attribute values when HTML syntax allows it. That does not guarantee every crawler, social preview service, email client, template pipeline or downstream parser will interpret the transformed markup exactly as your browser does.

The upstream html-minifier-terser project currently has an open v7.2.0 issue reporting that quote removal on Open Graph metadata can prevent WhatsApp from loading an og:image preview. Keep this option off unless you have tested the minified output with the actual consumers that read your HTML—especially Open Graph, Twitter/X card, structured-data-adjacent templates and machine-consumed metadata.

Optional HTML5 cleanup

Enable HTML5 cleanup when the destination is modern HTML5 and you want the minifier to remove common legacy verbosity. The option can shorten an older doctype to <!doctype html>, collapse boolean attributes such as disabled="disabled" to disabled, remove type="text/javascript" from script tags, and remove type="text/css" from style/link tags. It remains off by default because older documents or compatibility workflows may intentionally retain those forms.

Inline CSS and JavaScript minification

Enable the CSS or JavaScript options only when you specifically want code inside style or script content compressed as well. They are disabled by default because HTML compression and language-specific code compression are separate operations, with different parsing rules and debugging tradeoffs.

Minification is not performance optimization by itself

A smaller HTML document can reduce transfer size, but modern HTTP compression already removes many repeated bytes efficiently. Real page performance can also depend on server latency, render-blocking resources, JavaScript execution, images, fonts, caching, network protocol and Core Web Vitals. Treat HTML minification as one build optimization rather than a complete speed strategy.

Minification runs outside the main browser thread

The underlying html-minifier-terser parser can perform expensive work on pathological input. Smart Web Utility therefore runs each minification in a dedicated Web Worker rather than on the page's main thread. If a run exceeds eight seconds, the worker is terminated and the page returns a recoverable timeout error instead of allowing that job to keep the interface busy indefinitely. Starting a new run or clearing the tool also cancels the previous worker.

When the page starts, it preflights the pinned html-minifier-terser 7.2.0 browser bundle in a Web Worker. jsDelivr is tried first; if that engine does not become ready within ten seconds or reports a startup error, the page retries the same pinned version from UNPKG. The status changes to Ready only after one provider has successfully initialized. If neither provider works, the page reports the engine-load error before you start a minification job. Only the library asset is fetched from those CDNs; the HTML you paste or open stays in the browser and is sent only to a local worker.

This timeout is an availability guard, not a statement that every valid large document will finish within eight seconds. If legitimate production HTML repeatedly reaches the limit, use a controlled build pipeline where you can choose resource limits appropriate to that project.

Malformed or partial HTML

A production minifier must parse source structure in order to transform it. Malformed fragments or deliberately incomplete markup can therefore be normalized differently from the original text. Keep source files in version control and test the resulting page, especially when minifying templates, server-side fragments or nonstandard markup.

Templates and embedded syntax

HTML files used by template engines can contain delimiters that are not ordinary HTML. This tool does not promise compatibility with every framework template language. If a file contains server-side directives, custom placeholders or build-system syntax, compare the output carefully before replacing the source.

Frequently asked questions

Does minifying HTML change the page?

Conservative minification is intended to preserve normal browser behavior, but aggressive options and unusual markup should always be tested with the browsers and downstream consumers that matter to your deployment.

Is removing attribute quotes always safe?

No. The minifier only removes quotes where HTML syntax permits unquoted values, but downstream parsers and social-preview services can still behave differently. The option stays off by default; test metadata and machine-consumed HTML before enabling it in a production build.

What does HTML5 cleanup change?

It can shorten the doctype, collapse standard boolean attributes, and remove legacy JavaScript/CSS type attributes that HTML5 does not require. It is opt-in.

Does this minify CSS and JavaScript too?

Only when you explicitly enable the inline CSS or inline JavaScript options.

Can I minify an HTML file?

Yes. Open a local .html or .htm file up to 5 MB.

Is HTML uploaded to the server?

No. Your HTML is processed in a local Web Worker. The page fetches the minifier library asset from a pinned CDN source, with a second CDN as a startup fallback, but it does not send your HTML content to either CDN.

What happens if the primary minifier CDN fails?

The page preflights the pinned jsDelivr bundle first. If it cannot become ready within ten seconds or returns a startup error, the page retries the same pinned version from UNPKG. “Ready” appears only after one provider successfully initializes.

What happens if minification takes too long?

The minifier runs in a Web Worker. A single run is stopped after eight seconds so pathological input cannot indefinitely block the page interface. You can also clear the tool to cancel an active run.

Should I keep the original HTML?

Yes. Keep source markup in version control or another backup and deploy minified output as a build artifact.
