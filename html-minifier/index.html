Minify HTML without uploading the document

This HTML minifier compresses source markup in browser JavaScript. Its conservative default profile removes ordinary comments, collapses unnecessary whitespace and removes redundant HTML attributes while avoiding more aggressive transformations unless you explicitly enable them.

Whitespace compression

Indentation and repeated whitespace can often be reduced without changing how normal HTML content is interpreted. Conservative collapse is used to avoid stripping every possible text boundary aggressively.

Comment removal

Regular HTML comments can be removed to save bytes. Conditional or tool-specific comments can matter in legacy workflows, so review output when your document depends on unusual comment syntax.

Redundant attributes

Some attributes have defaults that HTML already implies. The minifier can remove recognized redundant forms while leaving application-specific data attributes intact.

Exact byte savings

The tool reports input bytes, output bytes and percentage saved so you can measure whether a transformation is worth using rather than assuming every file benefits equally.

Why aggressive options are disabled by default

HTML minification is not merely deleting spaces. Removing optional tags, stripping safe attribute quotes, sorting attributes, or rewriting inline CSS and JavaScript can create larger semantic or debugging changes than basic whitespace compression. Those controls are available, but they are opt-in so a first run remains conservative.

Inline CSS and JavaScript minification

Enable the CSS or JavaScript options only when you specifically want code inside style or script content compressed as well. They are disabled by default because HTML compression and language-specific code compression are separate operations, with different parsing rules and debugging tradeoffs.

Minification is not performance optimization by itself

A smaller HTML document can reduce transfer size, but modern HTTP compression already removes many repeated bytes efficiently. Real page performance can also depend on server latency, render-blocking resources, JavaScript execution, images, fonts, caching, network protocol and Core Web Vitals. Treat HTML minification as one build optimization rather than a complete speed strategy.

Malformed or partial HTML

A production minifier must parse source structure in order to transform it. Malformed fragments or deliberately incomplete markup can therefore be normalized differently from the original text. Keep source files in version control and test the resulting page, especially when minifying templates, server-side fragments or nonstandard markup.

Templates and embedded syntax

HTML files used by template engines can contain delimiters that are not ordinary HTML. This tool does not promise compatibility with every framework template language. If a file contains server-side directives, custom placeholders or build-system syntax, compare the output carefully before replacing the source.

Frequently asked questions

Does minifying HTML change the page?

Conservative minification is intended to preserve normal document behavior, but aggressive options and unusual markup should always be tested.

Does this minify CSS and JavaScript too?

Only when you explicitly enable the inline CSS or inline JavaScript options.

Can I minify an HTML file?

Yes. Open a local .html or .htm file up to 5 MB.

Is HTML uploaded to the server?

No. The document is processed in your browser on this page.

Should I keep the original HTML?

Yes. Keep source markup in version control or another backup and deploy minified output as a build artifact.
