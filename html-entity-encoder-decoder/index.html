Encode or decode HTML character references

Encode the HTML-sensitive characters &, <, >, double quotes and apostrophes as readable named essentials or numeric decimal/hex references. Turn on Encode non-ASCII when you also want characters such as é or emoji represented numerically. Decode mode resolves one layer of browser-recognized named and numeric character references back to plain text.

What HTML character references are

HTML character references can be named, decimal numeric or hexadecimal numeric. For example, a less-than sign can be written as &lt;, &#60; or &#x3C;. The HTML Living Standard defines these three forms, while MDN summarizes common named and numeric references.

When HTML entities are useful

Encoding is useful when you want literal markup characters to appear as text instead of letting the browser interpret them as HTML. Decoding converts named or numeric entities back to their readable characters for inspection, editing or data cleanup.

Named essentials

Use readable forms such as &amp;, &lt;, &gt; and &quot;. Apostrophes use &#39;. When non-ASCII encoding is enabled in this mode, those extra characters use decimal references rather than a bundled name table.

Decimal or hex

Numeric references represent Unicode code points directly. For example, é can be &#233; or &#xE9;, and emoji use their full Unicode code point rather than broken UTF-16 surrogate halves.

Decode one layer

Decode mode uses the browser's HTML parser once. For example, &amp;lt; becomes &lt;, not <. Run decode again only when the source is intentionally double-encoded.

Local conversion

The encoder and decoder run in your browser. Decoded output stays in a plain-text field and is not rendered as HTML.

Entity encoding is not a complete XSS defense

Escaping rules depend on the destination context: HTML text, quoted or unquoted attributes, JavaScript, CSS and URLs have different requirements. This tool converts character references; it does not sanitize markup, validate a template, or make arbitrary untrusted content safe for every context. Use your framework's context-aware escaping and sanitization controls in production.

Example: showing markup without rendering it

If documentation needs to display <strong>Sale</strong> as literal text, escape the markup characters in the HTML source. Named essentials are easiest to read, while decimal or hexadecimal references are useful when you need an explicit numeric representation. Enable non-ASCII encoding only when the destination workflow actually requires it; ordinary UTF-8 HTML can contain characters such as é and emoji directly.

Decode carefully before editing

Entity decoding is useful when inspecting feed data, CMS exports or API fields, but decoded output can contain real markup characters. If you later insert that text into a webpage, apply the destination framework's context-aware escaping or sanitization rather than trusting previously encoded input.

Related developer workflow

Use the URL Encoder / Decoder for URL component escaping and the Base64 Encoder / Decoder for Base64 data. These formats solve different problems, so do not treat them as interchangeable security controls.
