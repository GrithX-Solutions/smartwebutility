XML Sitemap Checker & Validator

Check a public sitemap or sitemap index for protocol structure, absolute locations, duplicate URLs, lastmod quality and common submission problems.

Validate a public XML sitemap or sitemap index

Enter a public sitemap URL to follow a small, safety-bounded redirect chain, parse the final XML and validate the direct entries against core Sitemap protocol rules. The checker reports protocol issues separately from warnings so a parseable file is not automatically treated as a good sitemap.

What this sitemap validator checks

The checker accepts the standard urlset and sitemapindex roots, verifies the Sitemap protocol namespace, requires one non-empty absolute HTTP(S) loc per direct entry, checks the 50,000-entry limit, identifies duplicate locations and validates lastmod values. It also reports host diversity and previews up to 20 valid locations.

Namespace and root

Valid XML alone is not enough. The checker requires a urlset or sitemapindex root and verifies the standard http://www.sitemaps.org/schemas/sitemap/0.9 namespace.

Location quality

Each direct entry must contain one non-empty loc with a fully qualified HTTP(S) URL no longer than 2,048 characters. Duplicate locations are reported separately.

lastmod checks

When lastmod is present, the checker verifies a W3C-style date/date-time format and warns about clearly future-dated values. Google says it uses lastmod when the value is consistently accurate.

Redirect and size safety

The server follows at most three redirects and revalidates every destination against the existing public-host SSRF rules. It reads at most 2 MB; larger responses receive an explicit bounded-checker error rather than a false malformed-XML result.

What Google currently expects from sitemap URLs

Google's current sitemap guidance limits one sitemap to 50,000 URLs or 50 MB uncompressed and says sitemap URLs should be fully qualified absolute URLs. Google also ignores changefreq and priority, while accurate lastmod values can be useful. See Google Search Central's sitemap guidance and the Sitemaps protocol.

Sitemap versus sitemap index

A normal sitemap uses a urlset root and lists page URLs. A sitemap index uses a sitemapindex root and lists child sitemap files. Indexes are useful for larger sites or for separating content groups such as products, articles, images or languages.

Important limits of this checker

This remains a bounded structure/protocol checker, not a site crawler. The server reads at most 2 MB even though Google's sitemap limit is much larger; files above this tool limit receive a clear error because partial XML cannot be validated honestly. The checker does not recursively fetch child sitemaps, request every listed URL, inspect page canonicals/noindex directives, validate hreflang return links or certify search-engine indexing.

Frequently asked sitemap questions

Does putting a URL in a sitemap guarantee indexing?

No. A sitemap helps search engines discover URLs, but indexing still depends on crawl access, page quality, canonicalization, robots directives and other signals.

Can a sitemap contain redirected URLs?

It can technically list them, but a clean sitemap should normally contain the canonical destination URLs you want crawled and indexed rather than avoidable redirect sources.

Does this tool check every child sitemap in an index?

No. It validates the index document itself, counts direct child sitemap locations and previews a sample. Each child sitemap must be checked separately.

What happens if the sitemap is larger than this checker's 2 MB safety limit?

The checker stops and reports the local tool limit instead of trying to parse incomplete XML. That 2 MB ceiling is a Smart Web Utility resource-safety limit, not Google's sitemap limit; Google currently allows up to 50 MB uncompressed and 50,000 URLs per sitemap.

Does this checker follow sitemap redirects?

Yes, up to three hops. Every redirect destination is revalidated as a public HTTP(S) target so redirect handling does not bypass the network-tool SSRF protections.
