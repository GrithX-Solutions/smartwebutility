Escape XML characters using the correct context

XML escaping depends on where a value will be inserted. Element character data, a double-quoted attribute and a single-quoted attribute do not need exactly the same replacements. This tool exposes those contexts separately instead of applying one unexplained replacement rule to every string.

Element text

Text mode escapes ampersands and less-than signs, and conservatively escapes greater-than signs as well. This also prevents an accidental ]]> sequence from appearing in ordinary character data.

Double-quoted attributes

Double-quoted attribute mode additionally converts the double quote to &quot; so the value cannot prematurely close a "..." attribute.

Single-quoted attributes

Single-quoted attribute mode converts the apostrophe to &apos; while escaping XML markup delimiters.

All five entities

The all-five mode converts ampersand, less-than, greater-than, apostrophe and quotation-mark characters to XML's predefined entity references.

The five predefined XML entities

XML defines &amp;, &lt;, &gt;, &apos; and &quot; as predefined general entities. Unlike HTML, XML does not provide a large built-in vocabulary of named entities such as &copy; unless a document type or another vocabulary declares them.

Unescape predefined and numeric references

Unescape mode decodes the five predefined entity references plus decimal references such as &#38; and hexadecimal references such as &#x26;. Decoding is single-pass: text such as &amp;lt; becomes &lt;, not immediately <, which avoids silently removing two encoding layers at once.

XML 1.0 character validity

Escaping a character does not make every Unicode code point legal in XML 1.0. Most control characters below U+0020 are not permitted, with tab, line feed and carriage return as exceptions. Escape modes reject disallowed XML 1.0 characters rather than pretending entity encoding can make them valid.

Escaping is not XML validation

This tool transforms text. It does not verify matching tags, namespace declarations, document structure, DTD rules or XSD schema validity. Use the XML Formatter & Validator when you need to check whether a complete XML document is well formed.

Why ampersands must be handled first

When escaping, a literal ampersand must be converted before other entity strings are created. Otherwise the ampersands introduced by &lt; or &quot; could be encoded again. The browser implementation performs replacements in an order that avoids that double-encoding mistake within one operation.

Frequently asked questions

Which characters must be escaped in XML text?

Ampersand and less-than signs cannot appear literally as ordinary XML character data. Greater-than signs are also escaped conservatively by this tool.

How do I escape quotes in an XML attribute?

Use the mode that matches the attribute delimiter. Double-quoted attributes need &quot;; single-quoted attributes need &apos;.

Does XML support HTML named entities?

Only five named entities are predefined by XML itself. Other names require an applicable declaration.

Can it decode numeric XML entities?

Yes. Decimal and hexadecimal character references are decoded when they represent characters allowed by XML 1.0.

Is my text uploaded?

No. Processing runs locally in browser JavaScript.
