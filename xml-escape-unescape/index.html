Escape XML characters with the right context

XML uses a small predefined entity set: &amp;, &lt;, &gt;, &apos; and &quot;. This tool applies them according to the selected text or attribute context instead of treating XML as if it were HTML.

Element text

Text mode escapes ampersand, less-than and greater-than signs. Escaping > everywhere is conservative; XML primarily requires it when needed to avoid the ]]> sequence in character data.

Double-quoted attributes

In addition to markup characters, double quotation marks are encoded as &quot; so the value cannot terminate a double-quoted XML attribute.

Single-quoted attributes

Single quotation marks are encoded as &apos; when the surrounding XML attribute uses apostrophes as its delimiter.

All five entities

Use the all-five mode when you want a deterministic representation that replaces every predefined XML delimiter character regardless of the eventual text or attribute context.

XML unescape behavior

Unescape mode decodes the five predefined named entities plus decimal references such as &#169; and hexadecimal references such as &#x1F600;. Decoding happens once, so an input such as &amp;lt; becomes &lt;, not a literal less-than sign.

Unknown named entities are preserved

Unlike HTML, XML does not have a large built-in catalog of named entities. A reference such as &nbsp; is not one of XML's five predefined names. Documents can define custom entities in a DTD, but a standalone string tool cannot know those declarations safely, so unknown named references remain unchanged and are reported as warnings.

Numeric character references

XML can represent characters by decimal or hexadecimal Unicode code point. This decoder only converts numeric references that fall inside the XML 1.0 character ranges. Invalid references, including disallowed control-code references, stay unchanged and are counted as warnings instead of being replaced with an arbitrary character.

Invalid XML 1.0 characters cannot be escaped

Escaping markup delimiters does not make every Unicode code point legal in XML 1.0. XML 1.0 permits tab, line feed, carriage return, and specific Unicode ranges; it excludes NUL, most C0 control characters, surrogate code points, U+FFFE and U+FFFF. Escape mode now stops and identifies the first invalid code point instead of returning output that still cannot appear in a well-formed XML 1.0 document. Writing an illegal character as a numeric reference does not make it valid. See the W3C XML 1.0 character rules.

Escaping versus CDATA

CDATA sections are a different XML mechanism. Inside a CDATA section, ordinary ampersands and angle brackets can appear without entity escaping, but the closing sequence ]]> cannot appear as content. This tool escapes normal XML character data and attribute values; it does not create or split CDATA sections automatically.

Avoid accidental double escaping

Escape mode treats every ampersand as data. If the input already contains &amp;, escaping it again produces &amp;amp;. This is deliberate because automatically guessing which ampersands are already trusted entity references can change the original string. Use unescape first when you intentionally need to normalize already-encoded text.

XML escaping is not full XML validation

Escaping makes text suitable for a particular XML context, but it does not check tag nesting, namespace declarations, schemas, DTD rules or document structure. Use the XML Formatter & Validator when you need a complete well-formedness check after inserting escaped content into a document.

Frequently asked questions

Which characters must be escaped in XML?

Ampersand and less-than signs require escaping in ordinary XML character data. Attribute delimiters also need encoding when they match the quote character surrounding the value.

Is &nbsp; a predefined XML entity?

No. The predefined XML entity names are amp, lt, gt, apos and quot.

Can it decode numeric XML entities?

Yes. Valid decimal and hexadecimal character references are decoded.

Can escaping make an illegal XML 1.0 control character valid?

No. Escape mode reports XML 1.0-illegal code points such as U+0000 instead of returning falsely XML-safe output. Numeric references must also point to characters allowed by XML 1.0.

Does it decode custom DTD entities?

No. Unknown named entities are left unchanged because their replacement text depends on declarations outside the pasted string.

Is the input uploaded?

No. Escape and unescape processing runs locally in browser JavaScript.
