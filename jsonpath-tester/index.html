Test JSONPath expressions against real JSON

A JSONPath expression selects nodes from a JSON document in a way that is conceptually similar to using a path to navigate nested data. This tester evaluates the query against the JSON you provide and returns the matching values, their normalized paths, or a combined path-and-value result.

Matched values

Use value mode when you want the data selected by the JSONPath expression, such as every book title, a filtered set of records, or one deeply nested property.

Normalized paths

Use path mode when the location of each match matters. Normalized paths identify matched nodes using canonical bracket notation such as $['store']['book'][0]['title'].

Path plus value

Combined mode is useful for debugging because it shows both where a match came from and the JSON value at that location.

Expression validation

The evaluator uses an RFC 9535 implementation that parses and validates JSONPath expressions before returning results, so malformed expressions are reported rather than silently guessed.

Common JSONPath examples

$.store.book[*].title selects every title in the book array. $..author finds descendant members named author. $.store.book[0] selects the first book. RFC 9535 filter expressions can select nodes based on conditions, such as price or string length, when the expression follows the standard grammar.

JSONPath finder versus JSON search

A text search only tells you that a string appears somewhere in a JSON document. JSONPath works on parsed structure, so it can select values by object member, array index, wildcard, descendant segment, slice or filter. Normalized-path output also makes the exact location of each selected node explicit.

JSONPath is not JSON Pointer

JSONPath is a query language that can return multiple nodes. JSON Pointer identifies one location with a compact slash-based syntax. A normalized JSONPath may look like a location identifier, but the query language can also include wildcards, filters and descendant selection that JSON Pointer does not provide.

RFC 9535 behavior

This page uses an implementation of the standardized JSONPath syntax defined by RFC 9535. Some older JSONPath tools implement historical extensions or library-specific expressions that are outside the standard. A query that works in a legacy engine may therefore need adjustment when tested against standardized JSONPath semantics.

Filters and data types

Filters evaluate JSON values using JSONPath rules rather than JavaScript source-code execution. Strings, numbers, booleans, null values, arrays and objects remain distinct JSON types. If a condition does not match the document shape or uses invalid function arguments, the evaluator can reject the expression or return no matches.

Privacy and local JSON analysis

The JSON document and JSONPath expression are processed in browser JavaScript and are not submitted to a Smart Web Utility query API. Remove secrets before sharing screenshots, downloaded results or copied output with other people.

Frequently asked questions

What is a JSONPath tester?

It evaluates a JSONPath query against JSON and shows which nodes the expression selects.

Can it show the path of every match?

Yes. Choose normalized paths or path + value output.

Does it support JSONPath filters?

Yes, when the expression follows the RFC 9535 grammar supported by the evaluator.

Can I open a JSON file?

Yes. Local JSON files up to 5 MB can be opened directly in the browser.

Is my JSON uploaded?

No. Evaluation runs locally in browser JavaScript.
