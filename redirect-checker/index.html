How to use the redirect checker

  1. Enter the complete starting URL, including http:// or https://.
  2. Select Trace Redirects.
  3. Read the chain from the original request through each 3xx response to the final status.
  4. If there are several hops, review whether older redirects can point directly to the final canonical URL.
  5. If a loop is reported, compare the repeated URLs and then inspect CDN, proxy, web-server and application redirect rules.

How to read redirect checker results

200 or another final status

The chain has reached a non-redirect response. Confirm that the final URL and response are the destination you intended.

301 or 308

The server is communicating a permanent move. These are commonly used for durable URL migrations and canonical hostname changes.

302 or 307

The server is communicating temporary routing. Check whether the temporary behavior is intentional for the requested URL.

Repeated URL or too many hops

The redirect rules may conflict or form a cycle. Trace the first point where the URL starts repeating or switching between schemes, hosts or paths.

Why redirect chains matter

Redirects are normal infrastructure, but unnecessary hops add connection and request latency. Long historical chains also make migrations harder to reason about. Where possible, old URLs should point directly to the correct current destination rather than passing through several previous URL structures.

Common redirect patterns to inspect

HTTP to HTTPS

Confirm the insecure URL moves to the intended HTTPS hostname and does not bounce through extra host or path variations.

www and non-www normalization

Make sure the preferred hostname is reached consistently and internal links already use the canonical version.

Domain or CMS migration

Check representative legacy URLs and important deep links. Redirect each old page to the closest relevant new page rather than sending everything to the homepage.

Tracking and short links

Inspect where marketing, affiliate or shortened links land and whether intermediate redirects introduce unexpected domains or parameters.

301 vs 302 vs 307 vs 308 redirects

The status code communicates whether a redirect is intended to be permanent or temporary and, for some request methods, whether the method and request body should be preserved.

301 Moved Permanently

Use a 301 when an old URL has permanently moved and clients should use the new location going forward. For site migrations and durable URL changes, Google recommends permanent server-side redirects when possible.

308 Permanent Redirect

Like 301, 308 communicates a permanent move, while explicitly preserving the request method and body. This distinction matters more for non-GET requests and application routes.

302 Found

Use a 302 for temporary routing when the original URL should remain the primary location. Historical client behavior can change non-GET requests to GET after some 302 responses.

307 Temporary Redirect

Use a 307 for a temporary redirect when the request method and body must be preserved. It removes the method-changing ambiguity associated with older 302 behavior.

A 303 See Other intentionally directs the client to retrieve the destination with GET. Always choose the status that matches the behavior of your application rather than selecting a code only for SEO.

Reference: Google's redirect guidance.

Limits of this checker

The server follows up to ten request steps and reports redirects visible to its HTTP client. Redirect behavior can still vary by cookie, authentication, user agent, geography, JavaScript execution or application state. Client-side JavaScript navigation is not the same as an HTTP redirect and may not appear in this chain.

Frequently asked redirect questions

How many redirect hops should a URL have?

There is no universal magic number, but fewer unnecessary hops are easier to maintain and faster for clients. A direct redirect to the intended destination is preferable when it is practical.

What causes a redirect loop?

Conflicting rules can send URL A to URL B and then send URL B back to URL A, or cycle through a larger set of URLs. Proxy, CDN, CMS and web-server rules can all contribute.

Why does my browser show a different redirect?

Cookies, login state, user agent, geographic routing, bot protection and A/B testing can change redirect behavior between clients.

Should internal links point to redirected URLs?

Usually it is better to update internal links to the final intended URL so normal navigation does not rely on avoidable redirect hops.

How do I check where a URL redirects?

Enter the original URL above and run the checker. The output shows the redirect status and Location target for each hop until the request reaches its final destination.

What is the difference between a 301 and 302 redirect?

A 301 communicates a permanent move, while a 302 is normally used for temporary routing. For non-GET requests, 307 and 308 make request-method preservation explicit.

Can this checker detect a redirect loop?

Yes. The checker tracks URLs already visited in the current chain and reports when a later redirect returns to one of them.
