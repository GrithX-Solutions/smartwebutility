Generate UUID v4 identifiers

UUID v4 values are 128-bit identifiers generated from random data. They are widely used for database keys, request IDs, test fixtures, distributed systems and other cases where globally unique identifiers are useful without coordinating a central counter.

When to use a UUID v4

Random UUIDs are useful when identifiers must be created independently across browsers, services or machines without asking a central counter for the next number. Typical examples include request IDs, test fixtures, import rows, temporary client-side objects and database keys where unpredictability is preferable to sequential numbering.

Uniqueness is probabilistic

A UUID v4 has a very large random space, making accidental collisions extremely unlikely in normal applications, but it is not a proof that a duplicate can never exist. Systems with strict uniqueness requirements should still enforce a unique constraint at the storage layer and handle the rare conflict correctly.

UUIDs are identifiers, not secrets

Do not treat a UUID as an authentication token merely because it looks random. Access control should use purpose-built credentials with appropriate entropy, expiration and verification. For secret-like random strings, use the Random String Generator and follow the security requirements of the receiving system.
