Reverse DNS explained

What a reverse DNS checker tells you

Reverse DNS starts with an IP address and looks for the hostname published in its PTR record.

A normal forward DNS lookup maps a hostname to an IPv4 or IPv6 address using records such as A and AAAA. A reverse DNS lookup goes the other direction: it takes an IP address, constructs its reverse DNS name and queries for a PTR (pointer) record.

PTR record

A PTR record maps an IP address back to a hostname. It is the core record returned by a reverse DNS or rDNS lookup.

IPv4 reverse DNS

IPv4 octets are reversed under in-addr.arpa. For example, 8.8.8.8 is queried as 8.8.8.8.in-addr.arpa.

IPv6 reverse DNS

IPv6 addresses are expanded into hexadecimal nibbles, reversed, and queried under ip6.arpa.

FCrDNS

Forward-confirmed reverse DNS checks whether a PTR hostname resolves through A or AAAA records back to the original IP address.

Resolver agreement

Google Public DNS and Cloudflare may temporarily show different cached answers after a PTR change. Comparing them helps distinguish propagation from a persistent configuration.

Who controls PTR?

The IP-space owner normally controls reverse DNS. That is often your ISP, VPS provider, cloud platform or hosting provider rather than the DNS provider for your ordinary domain zone.

Reverse DNS and email server checks

Reverse DNS is especially important for outbound mail infrastructure. Gmail's current sender guidelines require sending IP addresses to have valid forward and reverse DNS records, and the PTR hostname must resolve forward to the same sending IP. A passing PTR/FCrDNS check is only one part of mail delivery: SPF, DKIM, DMARC, TLS, reputation and sending behavior still matter.

How to check reverse DNS from the command line

On Linux and macOS, dig -x 8.8.8.8 +short performs a PTR lookup. nslookup 8.8.8.8 is another common option and is also available on Windows. This web checker performs the same public-DNS task while also comparing resolvers and checking the forward path.

What if an IP has no PTR record?

No PTR result is not a browser or HTTP failure; it means the queried public reverse DNS zone did not publish a PTR hostname for that address. If the IP is yours and you need reverse DNS, configure it through the provider that controls the address block. Adding a PTR record to the ordinary forward DNS zone for your domain will not normally change reverse DNS.

What this tool does not claim

This checker does not identify every website hosted on an IP address, prove who owns a hostname, calculate sender reputation or guarantee inbox placement. It checks public PTR data and forward DNS consistency. Private, loopback, documentation and other non-public IP ranges are rejected so the tool cannot be used to probe internal network names.

Reverse DNS FAQ

What is a reverse DNS lookup?

A reverse DNS lookup starts with an IP address and queries its PTR record to find the hostname published for that address.

What is a PTR record?

A PTR record maps an IP address back to a hostname in the reverse DNS hierarchy. IPv4 uses in-addr.arpa and IPv6 uses ip6.arpa.

What is forward-confirmed reverse DNS?

Forward-confirmed reverse DNS, or FCrDNS, means the PTR hostname resolves forward through A or AAAA records to the original IP address.

Who controls reverse DNS?

PTR records are normally controlled by the organization that owns or delegates the IP block, such as an ISP, cloud provider or hosting provider.
