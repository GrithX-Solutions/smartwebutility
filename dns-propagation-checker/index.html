DNS Resolver Checker

Compare the same DNS lookup through Google Public DNS, Cloudflare DNS and the Smart Web Utility server resolver. Review DNS status, TTL, DNSSEC AD evidence, latency and answer agreement.

Result

Compare Google, Cloudflare and the server resolver

This DNS Resolver Checker sends the same hostname and record type to Google Public DNS and Cloudflare's DNS-over-HTTPS JSON services, then runs the equivalent lookup through the resolver available to the Smart Web Utility server. The report keeps each resolver separate so you can compare evidence instead of collapsing different answers into one result.

DNS status

Google and Cloudflare expose a DNS response code separately from HTTP status. NOERROR, NXDOMAIN, SERVFAIL and REFUSED describe the DNS result even when the HTTPS request itself succeeded.

TTL by resolver

See the TTL values returned with the selected record type. Different TTLs can reflect separate recursive cache states even when the answer data already matches.

DNSSEC AD evidence

The public-resolver rows show the Authenticated Data flag when their JSON response exposes it. An AD value is resolver validation evidence; this page does not replace the deeper DNSSEC Checker.

Resolver latency

Compare how long each lookup took from the Smart Web Utility server environment. This is diagnostic timing from one location, not a global DNS performance benchmark.

Answer agreement without a fake propagation score

The checker normalizes the requested record type and reports whether Google and Cloudflare agree and whether the successful resolver paths return the same answer set. It also preserves the returned record data so CNAME chains and related records remain inspectable. Agreement means these resolver paths match now; disagreement tells you exactly where the observations differ.

Three resolver paths cannot prove worldwide DNS convergence. If your task is a global DNS propagation test across distributed country-level probes, use the Smart Web Utility homepage DNS propagation checker. This page intentionally owns the narrower resolver-comparison workflow.

Supported DNS records

A and AAAA

Compare IPv4 and IPv6 addresses after a hosting, CDN or origin change. Resolver disagreement can reveal a stale recursive cache or a recent record transition.

MX

Compare mail exchanger targets together with their priorities. The server-resolver output preserves MX priority rather than showing only the target hostname.

TXT

Compare SPF, verification and other text records. Multiple TXT answers can be legitimate, so the report treats the complete requested-type answer set as evidence.

CNAME, NS and CAA

Inspect aliases, nameserver targets and certificate-authority authorization records. Server-side CAA output includes flags, tag and value when PHP exposes them.

Why two public DNS resolvers can disagree

Recursive resolvers maintain independent caches. One may have refreshed after an authoritative DNS change while another still has an older cached answer. A resolver can also return a DNS-level error such as SERVFAIL while another answers normally. Compare DNS status, requested-type answers and TTLs before deciding whether the difference is cache-related or points to a configuration problem.

DNS Resolver Checker vs DNS Checker

Use this page when the question is whether named resolver paths agree. Use the DNS Checker for a focused single-resolver lookup with record values and TTLs. Use the DNSSEC Checker when you need DS, DNSKEY and validation-specific evidence, and the Reverse DNS Checker for PTR/rDNS checks.

Methodology and limitations

Google and Cloudflare are queried through their public DNS-over-HTTPS JSON endpoints. Their JSON responses expose fields such as DNS Status, the DNSSEC AD flag and answer TTL/data. The server row uses PHP's dns_get_record from the Smart Web Utility server environment, which does not expose the same DNS response-code or AD fields.

Cloudflare documents its JSON format as following Google's JSON schema, but JSON DNS-over-HTTPS is provider-defined rather than a formal IETF JSON wire format. Results are point-in-time observations from these resolver paths and can change as recursive caches expire.

Frequently asked DNS resolver questions

What does DNSSEC AD mean?

AD means Authenticated Data. A validating recursive resolver can set it when the returned data passed DNSSEC validation. Treat it as evidence from that resolver, not as a substitute for inspecting the complete DNSSEC chain.

Why do Google DNS and Cloudflare DNS return different answers?

They use independent recursive caches and can refresh at different times. Compare the DNS status, answer set and TTL from each resolver before assuming the authoritative record is wrong.

Does matching resolver output mean DNS has propagated everywhere?

No. Matching Google, Cloudflare and the server resolver only proves those observed paths agree at this moment. Use the homepage worldwide propagation checker when you need distributed country-level evidence.

What does NXDOMAIN mean?

NXDOMAIN means the resolver reports that the queried domain name does not exist. That is different from a successful response with no record of the selected type.

Which resolver does the server row use?

It uses the DNS resolver available to the Smart Web Utility server environment through PHP. It is a third comparison path, but it does not expose the same JSON status and DNSSEC AD fields as Google and Cloudflare.
